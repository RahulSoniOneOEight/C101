3. SECTIONS IN DETAIL
================================================================
3.1 Overview
- Product details: product name, card subtitle, product description
- Media: main product image URL + preview
- Organisation:
    category (required)
    selling channels: B2C / B2B checkboxes (tick both = both)
    product type, brand, manufacturer, model / part number,
    HSN code (tax), selling unit
- Specifications: name / value / unit rows, suggestions
- Search listing: tags
- Each card: expand/collapse, status chip (Complete, Optional,
  4 values, 1 image...), per-section Save when dirty
- New product: only Product details open; edit restores last state

3.2 Variants & offers
- Variants FIRST, then Pricing
- Compact table: Variant | Variant SKU | Seller | Details | B2C price | Open
- One focused editor at a time: Previous / Next / Close
- Variant requires: Seller*, Variant name*, Variant SKU*,
  description*, optional image
- Single variant opens automatically (it is the default SKU)
- Locked products explain why add/duplicate/remove/SKU edits are off
- Bulk SKU prefix + Fill blank SKUs only when 2+ variants need a SKU

3.3 Pricing
- One price per variant's seller offer
- B2C and B2B in one editor, one Save pricing
- B2C: MRP / list price, selling price, GST inclusive
- B2B: list, selling, MOQ, quantity tiers, GST
- Scheduling is OPTIONAL and OFF by default:
    [ ] Schedule this price  -> "Live as soon as it is saved"
    [x] Schedule this price  -> Starts / Ends datetime fields
  Applies to BOTH B2C and B2B.
- B2C schedules are stored on the offer and enforced by the
  catalogue: outside the window the product is not live.
- B2B schedules use the existing effective-window logic.
- No duplicate "offer price vs B2C price" entry: the summary strip
  was removed.

3.4 Inventory
- Compact table: Variant | SKU | Seller | Tryton | On hand | ATP | Open
- One expanded SKU: metrics, locations, staging ledger note,
  audited adjustment request (does not change Tryton stock)

3.5 Activity
- Audited product/lifecycle/seller changes, newest first

3.6 Review & visibility
- Per channel: Published / Offer / Price / Stock gates
- Published - Not live when a gate fails
- Every blocker has a Fix link to the owning view and field
- Saving after a Fix returns to Review with a fresh server check
- B2B issues are warnings, not B2C blockers

================================================================

  Product content -> Save changes (also Save on each card)
  One offer       -> Save pricing
  Bulk selection  -> Apply to N
  Inventory       -> Request adjustment (never a save)
- Save bar is pinned to the viewport, visible only when dirty
  (always visible while creating)
- Ctrl/Cmd+S saves product content
- Unsaved product/pricing blocks lifecycle actions
- Local autosave is labelled a recovery copy, not a save

5. CSV PRODUCT IMPORT
================================================================
Location: Products -> Import CSV -> /products/import

Flow:
 1. Download empty template / template with example row
 2. Upload CSV -> preview (first 20 rows)
 3. Validate -> per-row status
 4. Import N products -> results + Download errors

Template columns (26):
 product_title, card_subtitle, description, category, brand,
 manufacturer, model_number, product_type, hsn_code,
 unit_of_measure, image_url, tags, specifications,
 variant_name, variant_sku, variant_description,
 variant_image_url, seller,
 b2c_list_price, b2c_selling_price,
 b2b_list_price, b2b_selling_price, b2b_moq, b2b_tiers,
 stock_quantity, channel

Formats:
 - tags: semicolon separated        (plumbing;pipe)
 - specifications: Name=Value|Name=Value
 - b2b_tiers: min:price|min:price   (5:950|10:900)
   ranges are closed automatically (5-9, 10+)
 - seller: name OR seller code (sel_...)
 - channel: b2c (default) | b2b | both
 - prices in rupees, not paise

Rules:
 - one row = one product with one variant
 - SKU must be new; existing SKUs are rejected
 - category and seller must already exist
 - selling <= list
 - failed rows are skipped; valid rows still import
 - imported products follow the same publish, channel, offer,
   stock and pricing path as the studio
